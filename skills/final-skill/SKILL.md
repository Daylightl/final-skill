# 竞赛冲刺交付

## When to use
用户带着**任意一版**竞赛任务书（样题或正式卷）要在有限时间内交付可运行系统时启用。默认比赛时长 **3 小时**；同分比交卷时间更早者优先，因此总原则是：

**规定分拿满 → 尽早形成可交卷版本 → 再堆差异化与交付文档。**

本 Skill **禁止**把某份样题的业务细节写死成唯一方案。会议室 / 设备等只是样例实体；一切以**当场任务书**为准，用下方第一性原理拆解。

---

## 总原则（第一性原理）

1. **硬约束优先于功能创意**  
   端口、路径前缀、HTTP 方法、字段名、状态码类别、时间格式、交付文件名、服务可用性——任何一项踩雷都可能整块 0 分。

2. **评分为双轨**  
   程序化「接口核验」与人工「产品 / 体验 / 自主设计」分开。先锁死程序轨满分与启动可用性，再投入自主设计与交付说明。

3. **场景材料 = 隐藏需求清单**  
   每条抱怨、台账缺陷、组织约束都映射为一个可演示的产品能力。规定契约只保证通信格式；业务规则由选手从场景自行推断。

4. **少即是多（UX）**  
   前端只做用户不用说明书也能完成主路径的界面。每一个控件、颜色、文案都必须服务一个真实任务。

5. **交卷即可核验**  
   核验往往异步、选手不在场。冷启动、种子数据、OpenAPI、交付说明、前后端口必须一次过。

6. **速度是策略**  
   规定功能自测全绿后立即打「可交卷」标签。此后每加功能都可随时停手下交；不要为完美牺牲交卷时间。

---

## Phase 0 — 任务书拆解（开赛 8–12 分钟，禁止写业务代码）

读完整任务书与附件，产出作战卡（可写在 `BRIEF.md` 或对话置顶）：

### A. 硬约束卡（原文摘抄，勿凭记忆）
- 前端 / 后端固定地址与端口
- 接口风格、路径前缀、JSON、编码、时间与日期格式
- 成功 / 参数错误 / 不存在 / 业务冲突的状态码与错误体形状
- OpenAPI：规范版本、获取方式（HTTP + 根目录文件名）、与实现一致性规则、缺失时的处罚
- 启动与可用性：哪一端挂掉导致哪一块 0 分
- 初始 / 种子数据要求
- 交卷流程、交卷后是否禁改、未举手如何计时
- 允许的辅助资料（提示词、Skill 等）

### B. 规定契约卡（满分 checklist）
对「规定功能清单 / 接口契约」中**每一个**接口列出：
- 方法 + 路径 + 必填 / 可选字段 + 类型
- 成功状态码与响应必需字段
- 明确写出的失败码（如冲突 409）与响应附加字段
- 查询参数组合规则、状态机取值枚举
- 幂等 / 请求头 / 并发等横切要求

再对照「规定功能评分表」（若有）：把分值映射到「最小可证伪测试」。缺评分表时，按契约接口 × 常见判分点自建：创建可读、状态变更、筛选、冲突、释放、校验、404、并发、幂等、统计实时性。

### C. 场景痛点卡（自主设计 backlog）
通读业务背景与工作记录 / 台账样例：
- 每条痛点 →「用户目标 + 成功判据 + 演示一句台词」
- 优先级：P0 主界面一眼看懂且对应原文；P1 信任（权限、审计、审批）；P2 锦上添花（导入、图表）
- **本场只选 ≤3 个 P0**（3 小时内再多会拖死交卷）

### D. 交付物卡
- 必须存在的文件（如 `openapi.json`、交付说明的文件名与格式）
- 交付说明必须覆盖：功能 ↔ 页面 URL ↔ 截图；未写入则可能不核验
- 根目录 README / 启动命令是否要求

### E. 技术选型（任务书限栈则服从；否则默认）
- 后端：FastAPI + SQLite（单文件、易加锁、自动 OpenAPI）
- 前端：Vite + Vue 或 React；只引入必要样式，不堆皮肤库
- 进程：一键脚本同时起前后端；**后端单 worker**，避免多进程弄丢内存锁 / 幂等表
- 禁止开赛浪费在：微服务、复杂权限框架、主题市场式装修、与核验无关的动效

**Gate：作战卡齐了再进入 Phase 1。**

## Phase 1 — 时间盒（默认 3h；时长不同按比例缩放）

| 段 | 时钟 | 目标 |
|---|---|---|
| T0 拆解 | 0:00–0:12 | 作战卡完成 |
| T1 骨架 | 0:12–0:25 | 仓库、端口、健康检查、种子骨架、一键启动 |
| T2 规定 API | 0:25–1:20 | 契约内全部接口 + 校验 / 404 / 冲突 / 幂等 / 并发 |
| T3 自测锁分 | 1:20–1:35 | 自测全绿 → **打可交卷标签 v0** |
| T4 前端主路径 | 1:35–2:15 | 规定能力均可在 UI 完成；审美与信息架构一次到位 |
| T5 自主设计 P0 | 2:15–2:40 | ≤3 个 P0，全部可演示 |
| T6 交付说明 | 2:40–2:55 | 文档 + 截图 + 链接；OpenAPI 落盘与在线双检 |
| T7 冷启动交卷 | 2:55–3:00 | 杀进程重开、跑自测、举手 |

**提前交卷：** T3 之后任一时刻若风险升高（前端半残、文档未写），优先收束交付说明与稳定性，而不是再开新功能。目标是「规定分可满分 + 自主设计叙事清晰」的**最早**可交卷版本。

---

## Phase 2 — 骨架与工程纪律

1. 固定职责（目录名可改）：`backend/`、`frontend/`、根目录 OpenAPI 文件、交付说明、`scripts/dev` 一键启动、`scripts/selftest` 自测。
2. 后端监听任务书端口；CORS 放行前端源；错误体形状与任务书一字不差对齐。
3. 数据层：单一 SQLite；启动时 migrate + seed（实体按**当场场景**准备，勿从旧样题抄表名当真理）。
4. 健康检查：后端可访 + 前端首页可开即算 T1 完成。
5. OpenAPI：开发期用框架生成；**每次改接口后**导出到根目录规定文件名，并保证任务书要求的 GET 可取到同一份。

---

## Phase 3 — 规定功能实现套路（与具体资源名无关）

对契约中每一类资源，按同一模式：

1. **模型字段 ⊆ 契约**：响应必需字段必须有；扩展字段不破坏核验。
2. **创建**：校验 → 落库 → 返回约定状态码与形体。
3. **列表 / 过滤**：文档中的 query 均可选、可组合；结果必须与条件相符。
4. **状态机**：仅允许文档枚举；非法迁移 4xx，永不 5xx。
5. **时间冲突**（若有独占资源）：只与「有效中」状态比；区间重叠用半开或任务书语义；首尾相接默认不冲突（除非任务书写明）。冲突响应附带可识别的冲突对象字段。
6. **释放**：取消 / 归还后，同资源同时段必须可再成功占用。
7. **库存 / 容量**：实时聚合，禁止缓存假数；超额 4xx。
8. **统计**：全部实时 COUNT，禁止硬编码。
9. **输入校验**：结束早于开始、非正数量、缺必填、空串、非法枚举 → 4xx 且不落库。
10. **不存在 ID**：4xx（优先 404），禁止 5xx。
11. **幂等**：若要求请求头，同键返回首条；同时对「无请求头但体完全相同的连点」做短窗去重（评分脚本可能不带头）。
12. **并发**：占用路径加 DB 即时锁或进程锁 + 单 worker；用脚本并发 N 次断言仅 1 成功。
13. **全局异常处理**：未捕获也转约定错误体，杜绝 500 污染核验。

每完成一类资源，立刻补自测，再进入下一类。

---

## Phase 4 — 自测脚本（锁规定分）

自测必须覆盖作战卡 B 每一判分点，至少：
- 创建后列表可见
- 合法成功码与形体
- 过滤组合
- 冲突与冲突体字段
- 取消 / 归还后释放
- 校验三类（时间、数量、缺字段）
- 不存在 ID
- 统计随业务变化
- 并发互斥
- 幂等（带头 + 不带头连提）
- OpenAPI：根文件可解析、关键 path 存在、在线 GET 可下载且非空

**Gate：自测全绿才进入大前端与自主设计；该时刻记为可交卷 v0。**

---

## Phase 5 — 前端：审美与 UX（Less is more）

### 信息架构（一屏懂）
- **默认首页 = 当前态势**：空闲 / 占用 / 待办 / 风险（超期、冲突、待批）一眼可见，而不是空洞仪表盘。
- 主导航 ≤4 项，对应该场核心对象（以任务书实体为准）。
- 主路径：选资源 → 填最少字段 → 提交 → 明确成功反馈；失败用可读中文，贴近错误体 `detail`。

### 视觉与交互准则
- 留白充足；字号三级（标题 / 正文 / 辅助）；禁止花哨渐变与图标堆砌。
- 一主色 + 中性灰 + 语义色（成功 / 警告 / 危险）；状态用文字标签，不靠用户猜图标。
- 表格或时间轴二选一作为「真相来源」；把视觉焦点放在「下一步能做什么」。
- 表单：合理默认值；约束内联提示；日期时间用友好控件，提交前转为任务书 ISO。
- 空状态写清「为什么空 + 下一步点哪里」。
- **禁止**：无标签图标按钮、隐藏手势、必须 hover 才出现的关键操作、把英文堆栈甩给用户。

### 实现顺序
1. 布局壳 + 导航 + 首页态势  
2. 规定 API 对应的申请 / 变更 / 查询主路径  
3. 再挂 P0 自主设计入口（同一视觉体系，不做成「另一个产品」）

---

## Phase 6 — 自主设计（给评委看的差异化）

选择规则：
- 必须能指回场景原文某句痛点
- 必须在交付说明里有截图与一句业务价值
- 3 小时内总数 ≤3 个 P0；**做深不做宽**

若任务书出现「氛围编程 / FDE」等能力画像，用产品行为证明：**业务理解 → 需求提炼 → 可运行交付**，不要在文档里喊口号。

每个 P0 完成定义：数据模型 + API（可超出规定契约，但必须写入 OpenAPI）+ UI 主路径 + 交付说明条目 + 30 秒演示台词。

---

## Phase 7 — 交付说明（人工分主战场）

根目录交付文档（格式服从任务书；未指定则用 Markdown），结构固定：

1. **一句话产品**：解决谁的什么问题。
2. **启动方式**：如何起前后端、默认账号（若有）、种子数据说明。
3. **规定功能对照表**：功能名 | 接口 | 页面 URL | 截图。
4. **自主设计对照表**：痛点原文摘句 | 方案 | 页面 URL | 截图 | 演示步骤（≤3 步）。
5. **设计说明（短）**：信息架构、为何少即是多、关键业务规则如何从场景推出。
6. **OpenAPI**：根目录文件名 + 在线 URL。

截图：真实跑通界面；可轻微标注关键按钮；禁止大段空话与架构八股。  
**未写入文档的功能，按评委可能看不到处理。**

---

## Phase 8 — 交卷前 5 分钟清单

- [ ] 杀进程后仅用一键脚本冷启动
- [ ] 后端端口、前端端口均可访
- [ ] OpenAPI 根文件存在、非空可解析，且与在线 GET 一致
- [ ] 自测全绿
- [ ] 种子数据足够演示
- [ ] 交付说明含全部要计分功能的链接与截图
- [ ] 无调试 500、无 Lorem、无错误端口链接
- [ ] 举手交卷；之后不改代码与数据

---

## 交给 AI 编程工具时的附加约束

将本 Skill 与**当场任务书全文**一起提供，并要求模型：

1. 先输出作战卡（Phase 0），硬约束确认后再写代码。
2. 先实现并自测规定契约，再写 UI。
3. 禁止臆造契约外的「必做」接口；自主 API 必须进 OpenAPI。
4. 每轮结束前更新交付说明草稿与自测。
5. 用户说「收束交卷」时：停止新功能，只做 Phase 7–8。

---

## 反模式（显式禁止）

- 开赛先做漂亮首页或复杂动效
- 未读完整契约就自由发挥字段名 / 路径
- 多 worker + 纯内存幂等导致并发或幂等偶发失败
- 统计写死常数
- 交付说明只有架构叙述、无 URL / 无截图
- 自主设计超过 3 个，但规定自测未绿
- 把旧样题业务当成正式卷的假定需求

---

## 评审补丁（铁律与已定口径）

1. **自主规则不得污染规定接口**：审批、角色、黑名单、信用分等自主规则只作用于自主接口或自主字段；规定接口在评分脚本的「合法请求」下必须直接返回成功，不得因为待审批、未登录、缺扩展字段而拒绝。新增字段一律设为可选并给默认值。
2. **幂等口径**：带 `X-Request-Id` 的请求按请求头去重；不带请求头时，对「同一接口 + 请求体完全相同 + 10 秒内」的重复提交返回首条记录。两种去重结果都要持久化或放在单进程内。
3. **库存口径**：`active` 借用在归还或取消前一律占用库存，不论时段；可用量 = 总量 − active 借用数量之和。种子库存要给足，规定自测使用新建设备。
4. **OpenAPI 失败码**：每个接口都要显式声明 4xx/404/409 响应及 `{detail}` 结构，冲突响应还要声明 `conflict` 字段。
5. **停手标准（用户已确认）**：①规定功能自测全绿；②自主设计 ≤3 个 P0 均可演示；③交付说明链接与截图齐全（含 OpenAPI 双检）。三项齐了进入 Phase 8 并交卷，不再追加功能或打磨文档。
6. **可执行资产**：赛前准备好自测脚本模板（覆盖 Phase 4 全部用例并支持并发）、截图脚本（用 Playwright 按交付说明的 URL 批量截图），以及冷启动脚本。

---

## 正式卷优先原则（高于样题）

样题只用于练手与发现题型。正式卷字段、路径、实体、评分细则都可能变。Skill 执行时：

1. **只信当场任务书原文**；样题结论一律降级为「风险假设」，不得写成硬编码业务。
2. **先摘硬约束卡**（端口、状态码表、错误体、OpenAPI、可用性、交卷规则），再实现；条文与评分表冲突时：通信格式服从接口规范全文，判分放宽服从评分表（例如规范写 404、评分写「4xx 不限于 404」→ 实现仍返回 404，最稳）。
3. **工程手段服务原文后果**：异步核验、起不来 0 分、交卷后禁改 → 进程须脱离终端常驻、端口冲突失败要暴露（如前端 strictPort）、重启种子幂等；这些是手段，不是把样题端口写死。
4. **错误体对齐当场契约形体**：若契约把 `detail` 写成说明文字，则校验错误也要收成字符串，禁止框架默认数组直接出站。
5. **种子数据不得妨碍核验创建 / 占用路径**：自动化脚本使用的资源与时段不可预知。默认策略：种子以历史记录与基础主数据为主；若必须放「进行中 / 未来有效」占用，只挂在明确标注为演示专用的资源上，其余资源在任意合理时段都应可被成功创建占用。禁止依赖「我留了几个空档」这种赌法。
6. **不存在的外键 / 资源 ID**：若接口规范写明资源不存在返回某码（常见 404），实现用该码；同时保证绝不 5xx。
7. **并发与锁**：按当场评分的并发断言实现互斥；用 DB busy_timeout / 事务即时锁 / 单 worker，目标是「断言成功且无 500」，工具随栈选择。

## 交卷后进程常驻（用户硬要求）
异步核验时选手不在场，服务掉线 = 对应部分 0 分。交卷前必须：
- 前后端用 `nohup` / `setsid` / systemd user 等方式脱离终端常驻，关闭 SSH 或终端窗口后仍监听。
- 前端启用端口占用失败即退出（如 Vite `--strictPort`），避免静默落到错误端口。
- 一键启动脚本可重复执行：已在跑则复用或先停再起；种子数据幂等，重启不重复插入。
- 交卷前做一次「关终端 → 另开检查两个端口仍可访 → 再跑自测」的存活验证。

## 执行纪律（弱模型友好，必须遵守）

假设执行本 Skill 的编程 Agent **不会**自行补全契约细节、并发语义、错误体形状或交卷存活要求。用纪律补能力缺口。

### 硬规矩
1. **一次只做一个 Phase**（0→1→2…按序）。未声明当前 Phase、未给出该 Phase 的完成证据前，禁止进入下一 Phase。
2. **禁止一口气生成整仓**。单轮最多改：1 个后端模块，或 1 个前端页面，或 1 个脚本；改完立刻自检。
3. **先接口后前端写死**：T3 自测未全绿前，禁止写业务 UI（骨架壳除外）。
4. **每步必须跑自检并贴出结果**（命令 + 退出码 + 关键输出摘要）。声称「已完成」但无自检输出，视为未完成。
5. **契约字段逐字照抄**：路径、方法、字段名、状态枚举、错误体键名不得「同义替换」。开写前把相关契约片段粘进注释或测试。
6. **横切能力单独提交**：校验 / 404 / 冲突体 / 幂等 / 并发锁 / `detail` 字符串化 / OpenAPI 导出，各成一轮，各带自检。
7. **用户说「收束交卷」**：立即停止新功能，只做 Phase 7–8。

### 每 Phase 最低自检（按当场端口替换，勿写死样题数字以外的业务）
- Phase 1：两端口探活成功；一键脚本可重复执行。
- Phase 2–3：针对本轮改动的接口，用 curl/httpie 跑成功路径 + 至少 1 条失败路径。
- Phase 4：整份 `selftest` 全绿；含并发与幂等。
- Phase 5–6：主路径手点或脚本打开页面；截图文件落盘。
- Phase 7：交付说明每个要计分功能都有 URL；OpenAPI 根文件与在线 GET 一致、可解析。
- Phase 8：关终端后复探两端口；再跑一遍 selftest；确认进程常驻。

### 对用户（选手）的协作口令
- 「只做 Phase N」：Agent 不得越界。
- 「贴自检」：Agent 必须给出命令与结果。
- 「回滚上一轮」：丢掉未自检通过的改动。
- 「收束交卷」：进入 Phase 7–8。

### 弱模型易错清单（每轮结束默读）
- [ ] 错误体是字符串 `detail`，不是框架默认数组
- [ ] 不存在资源返回任务书规定码（常见 404），无 500
- [ ] 冲突响应带齐任务书要求的附加字段
- [ ] 统计非硬编码；取消/归还后名额释放
- [ ] 幂等：有请求头按头；无头则短窗同体去重
- [ ] 单 worker + 锁；并发断言只成功 1 次
- [ ] 自主规则未挡住规定接口的合法请求
- [ ] 种子未占用核验用的资源（演示占用隔离）
- [ ] 交卷后进程仍在监听

### 能力自适应（强模型快车道）
纪律的目的是防漏分，不是限速。按实际表现升降档：
- **升档条件**：作战卡一次准确覆盖全部契约 + 第一批接口一次自检全绿。
- **升档后**：允许一轮完成整组规定接口、或一轮完成一个完整页面；Phase 可合并推进。
- **不可放宽的闸门**：T3 selftest 全绿才进前端；每轮仍贴自检；交卷前 Phase 8 全做。
- **降档条件**：任一轮出现契约字段偏差、5xx 或自检失败 → 立即回到「一次一模块」。
- 强模型省下的时间优先用于：更早交卷 > 自主设计做深 > 交付说明打磨，而不是加更多功能。
